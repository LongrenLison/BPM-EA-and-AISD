# Clinic Letter 个人模块验收测试计划

范围：个人 Clinic Letter 原型，不包括小组整合或生产医院系统。只用虚构数据；发送、提醒、升级均为模拟。PASS 必须对应实际已运行层级；API、单元测试和界面练习不能互相替代。

## 前置条件与数据

- 本地 Camunda 8 Run 8.9.21 已由用户启动，REST 仅访问 loopback。
- Node.js 22 或以上；当前源已用 `node local-demo.mjs deploy --local-demo` 部署。
- 没有其他活动的秒级演示实例，也不同时运行第二个 Worker。
- 使用 `DEMO-CL-PERSONAL-…` 编号、`FOLLOW_UP` 类型、以 Synthetic 开头的临床文字，收件人角色码 `PATIENT,GP`，不填写真实地址。
- 正常版按诊疗完成时间计 7 天、1 个日历月、3 个日历月；秒级演示版为 10/20/30 秒。当前真实引擎测试使用秒级版。
- 每个 API 用户任务提交前取得部署绑定表单；API 提交不证明界面必填校验有效。

## 可复现执行

在本目录运行 `node --test tests/*.test.mjs`，进行离线测试。

对已启动的本地引擎，运行 `node local-demo.mjs test --local-demo`。脚本只创建和处理自己记录的演示实例，遇到其他活动实例停止，不自动取消它们。结果保存于 `evidence/personal-engine-latest.json`，历史批次另存时间戳文件。

## 场景与通过条件

| 编号 / 需求 | 操作与输入 | 通过条件 | 当前证据与边界 |
|---|---|---|---|
| CL01 正常流程 | 起草完整内容；医生批准；秘书两项检查 true、临床疑点 false | 模拟发送，COMPLETED、无待办/活动 incident；阶段与发送日期存在 | 新版秒级 API PASS；旧版正常界面已完成，新版结构化表单界面待练习 |
| CL02 医生退回 | 第一次 clinicalApproved=false，第二次更正后 true | 回到起草，再次审批后才可发送 | 新版 API PASS；异常界面待练习 |
| CL03 行政返工 | 分别将收件人核对、行政资料核对置 false，再置 true | 未完成时回到秘书，不发送；补全后完成 | 两字段各自独立 false 的 API PASS；两者同时 false 的组合未单独执行 |
| CL04 发送业务错误 | simulateDispatchError=true | 捕获 BPMN Error，生成 Retry 用户任务，不直接报成功 | 新版 API PASS；不代表真实邮件故障测试 |
| CL05 人工授权重试 | Retry 第一次授权 false，随后取消模拟错误、授权 true | 未授权继续待处理；授权后重新发送并完成 | 两条 API 分支 PASS |
| CL06 有限技术重试 | simulateTechnicalFailuresRemaining=2 | 恰好两次 job failure，实际重试数递减，随后完成；不用 BPMN Error 冒充技术失败 | 新版 API PASS；重试耗尽 incident、真实网络故障待测试 |
| CL07 延迟提醒 | 秒级版起草保持未完成，等首次提醒 | 提醒 job 实际完成，临床工作仍活动；后续为定时循环 | 首次提醒/循环结构验证；已批准抑制有单元测试；重复次数/精确时间/正式 7 天待测试 |
| CL08 一个月升级 | 秒级版仍未发送，等 20 秒里程碑 | 模拟经理通知完成，不替代临床批准 | 秒级 API PASS；正式日历月、真实通知送达待测试 |
| CL09 三个月升级 | 秒级版仍未发送，等 30 秒里程碑 | 模拟高层通知完成，临床工作仍 ACTIVE | 秒级 API PASS；正式日历月及管理动作待测试 |
| CL10 发送取消监测 | 各正常/异常路径发送完成，批次末再等 11 秒 | 八实例全部完成，五类演示 job 无可激活残留 | 本次 API PASS；各发送时间点完整矩阵与外部在途竞态待测试 |
| CL11 日历边界 | 1 月 31 日、闰年、时区、过去诊疗日期 | 实际 FEEL 与过期 timer 行为符合需求 | 待测试，部署成功不能替代此项 |
| CL12 权限 / 输出边界 | 不同真实身份与角色；行政尝试覆盖临床批准 | 仅获权医生批准；行政输出不覆盖临床字段 | 输出白名单有静态测试；真实 RBAC/引擎越权尝试待测试 |
| CL13 秘书临床疑点 | 已批准后秘书提交临床疑点 true | 返回医生起草；旧批准/核对清除，重新批准后才能发送 | 新版 API PASS，并检查旧 clinicalApproved=false；原因条件必填未实现 |
| CL14 日期与延迟历史 | 完成正常/返工任务，查询已完成历史 | 记录阶段起止、审批、行政处理、发送日期/方法；保留局部理由与引擎任务日期 | 新版 API/历史采集验证；draftStartedAt 是阶段进入时间，不是人工实际开工；不是生产审计系统 |

## 需求对齐

案例 Clinic Letter 段落：内容与收件人 → Draft 表单及 CL01；医生临床责任 → CL02/12/13；秘书行政责任 → CL03/13；分发失败 → CL04/05/06；逾期提醒/升级 → CL07/08/09/10/11；业务日期与延迟记录 → CL14。

原因可填写、回传和记录，但没有“拒绝/临床疑点时原因必须填写”的条件校验。发送方式仍是 SIMULATED_LOCAL；候选组名称不等于真实权限。这些保留为已知不足，不标成完成。

## 结果记录标准

每次记录：源 SHA-256（两模型、四表单、Worker、Adapter）、部署/流程版本、实例 key、步骤、预期/实际、状态、来源和时间。临床正文、真实地址、凭据不进入结果。时间戳原始批次不覆写；latest 只是最近批次。
